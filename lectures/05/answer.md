## 宿題（基礎）

### 取り組んだこと
`app/config.py` の `RAG_TOP_K` を5から3に変更し、同じ質問を `--trace` 付きで実行して比較した。

質問：
「第2回の説明では、LoRAは何を固定し何を学習しますか？QLoRAは何を加えますか？」

モデルは `gemini-3.5-flash-lite`、資料と質問は同じ条件とした。

### 比較結果

| 項目 | 変更前（5件） | 変更後（3件） |
|---|---|---|
| ツール | search_materials | search_materials |
| 主な根拠 | 第2回 p.51〜52 | 第2回 p.51〜52 |
| 回答 | LoRAは元の重みを固定して低ランク行列を学習。QLoRAは4bit量子化を追加 | 同じ内容を回答 |
| 時間 | 4.54秒 | 3.77秒 |
| 入力トークン | 3031 | 2077 |
| 出力トークン | 205 | 218 |
| 推定API費用 | $0.001422 | $0.001168 |

### traceで確認したこと
両条件とも `search_materials` が呼び出され、根拠として第2回の講義資料が取得された。ツール呼び出しは両条件とも1回で、モデル応答は2回だった。検索クエリの文言には多少の違いがあったが、正しい根拠を取得できた。

### 気づき・考察
検索件数を5件から3件に減らしても、今回は必要な根拠が残り、回答の正確性は維持された。一方で入力トークン数、時間、推定費用は減少した。

必要以上に情報を渡さないことは効率化につながると感じた。ただし、検索件数を減らすことで必要な根拠が取得できなくなる可能性もあるため、異なる質問や複数回の実験による検証が必要だと考える。
